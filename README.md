# Vision AI 검사 콘솔 — 웹 UI/UX 시안

화이트보드 스케치(S/N 입력 → 위치 선택 → 검사 → 결과 → Fail 당시 화면)와 장비 디스플레이 사진을 바탕으로 만든 웹 UI 시안입니다.
두 가지 밝은 톤 시안이 있습니다.

| 폴더 | 시안 | 특징 |
| --- | --- | --- |
| `/` (루트) | **시안 B** | 왼쪽 세로 단계 레일, 따뜻한 오프화이트 배경, 청록 포인트, 큰 터치 버튼, 카메라 중심 레이아웃 |
| `v1/` | 시안 A | 상단 바 + 카드 패널, 파란 포인트, 관리자 대시보드 스타일 |

두 시안 모두 기능·흐름·데이터 구조는 같고, `index.html`을 브라우저에서 열면 바로 동작합니다. 빌드·설치·외부 네트워크가 필요 없습니다.

> 아래 **100회 이상을 한눈에** 설계는 시안 B(루트)에만 적용되어 있습니다. 시안 A(`v1/`)는 이전 그대로입니다.

권장 폭은 1440px 이상입니다. 1280px에서는 결과 표가 가로로 조금 넘치지만 회차·판정 열이 고정되어 있어 그대로 읽을 수 있고, 820px 이하에서는 단 구성이 세로로 바뀝니다.

## 화면 미리보기

`index.html?screen=running` 처럼 `screen` 값을 주면 해당 화면의 샘플 상태로 시작합니다. `&preview=1`을 붙이면 아래 시안 도구 막대를 숨깁니다.

| screen 값 | 화면 |
| --- | --- |
| `serial` | 01 · S/N 입력 (Cancel / OK) |
| `position` | 02 · 위치 선택 (1·2 나란히, 3은 오른쪽 끝) |
| `ready` | 03 · 검사 준비 (▷ ⏸ ◻, 현재 개수 / 100) |
| `running` | 04 · Vision AI 감지 중 (회차 맵 실시간) |
| `paused` | 05 · 일시정지 |
| `stop` | 06 · 중지 확인 (◻ → 위치 완료 표시) |
| `position-progress` | 07 · 위치 1 완료 후 위치 선택 |
| `position-done` | 08 · 세 위치 완료 → 결과 보러 가기 |
| `results` | 09 · 결과 · 전체 600회 회차 맵 |
| `fail-detail` | 10 · Fail 클릭 → Fail 당시 화면 |

## 100회 이상을 한눈에

한 번 검사하면 위치 3곳 × 모드 2개 × 100회 = **최대 600회**가 쌓입니다. 표만 길게 늘어놓으면 스크롤 말고는 볼 방법이 없어서, 아래 다섯 가지로 설계했습니다.

**1. 회차 맵** — 칸 하나가 1회입니다. 100회를 25칸 × 4줄로 그려 스크롤 없이 전부 보여주고, 결과 화면의 `전체` 탭에서는 6개 그룹을 세로로 쌓아 600회를 한 화면에 담습니다. 초록=Pass, 빨강=Fail, 옅은 노랑=신뢰도 80% 미만, 빗금=아직 안 찍은 회차. Fail 칸을 누르면 그 회차의 Fail 당시 화면이 바로 열립니다. 검사 중에는 오른쪽 열에서 실시간으로 채워지며, 마지막 회차 칸에 테두리가 붙습니다.

**2. 항목별 Fail** — 100회가 넘어가면 "몇 번째 행이 틀렸나"보다 "어느 항목이 계속 틀리나"가 먼저 필요합니다. Energy·J/shot·Booster·Repeat·Length·Mode·Status 중 어긋난 횟수를 막대로 세워 정렬합니다. 막대를 누르면 그 항목이 어긋난 회차만 남고, 회차 맵도 해당 칸만 남기고 흐려져 어디에 몰려 있는지 보입니다.

**3. 필터** — `전체` / `Fail` / `신뢰도 80%↓` 로 좁힙니다. 600회 중 Fail 33회만 한 목록으로 모아 볼 수 있습니다.

**4. 기준값 고정 행 + 같은 값 흐리게** — 표 머리 바로 아래에 기준값 행이 고정됩니다. 기준과 같은 값은 회색으로 물러나고 어긋난 값만 굵은 빨강으로 남아서, 100행이 거의 같은 숫자로 채워져 있어도 다른 값만 눈에 들어옵니다. 신뢰도 80% 미만은 주황 점선 밑줄입니다.

**5. 항상 보이는 회차와 판정** — 열이 많아 표가 가로로 넘칠 때도 맨 왼쪽 `#`(위치·모드·회차)과 맨 오른쪽 `P/F`는 고정되어 따라옵니다. `Fail 이동 ↑ ↓` 로 Fail 행만 건너뛰며 훑을 수 있습니다.

| screen | 화면 |
| --- | --- |
| `results` → Fail 칩 | 11 · Fail 33회만 |
| `results` → 항목별 Fail 막대 | 12 · 한 항목이 어긋난 회차만 |
| `results` → 그룹 탭 | 13 · 한 위치·모드 100회 |

## 숫자 감지 (카메라 입력 패널)

`assets/device-sample.jpg`(장비 디스플레이 사진) 위에 11개의 감지 영역(ROI)을 그립니다. 좌표는 원본 사진(2000×1500) 픽셀 기준이며 `app.js`의 `FIELDS` 배열에 있습니다.

| 항목 | 사진의 값 | 판정 |
| --- | --- | --- |
| Energy | 1.0 | 기준값 비교 |
| J/shot | 16.67 | 기준값 비교 |
| Booster | 3.0 mm | 기준값 비교 |
| Repeat | 0.1 s | 기준값 비교 |
| Length | 25 mm | 기준값 비교 |
| Mode | MP / Normal | 기준값 비교 |
| Status | STANDBY | 기준값 비교 |
| Remain · Current · Total · Shot count | 118 · 436 · 436 · 436/300 | 기록만 |

기준값이 있는 항목이 모두 일치하면 Pass, 하나라도 다르면 Fail입니다. 각 항목의 ROI 잘라낸 이미지와 신뢰도를 사진 아래 스트립에 함께 보여줘 OCR 결과를 눈으로 검증할 수 있습니다.

ROI 좌표는 Tesseract OCR로 검증했습니다. 4배 확대·대비 보정·반전 전처리 후 11개 항목 모두 사진의 값과 같게 읽혔습니다.

## 실제 연결 지점

- `detectFrame(position, mode, i)` — 지금은 시뮬레이션입니다. 카메라 프레임을 `FIELDS[].roi`로 잘라 OCR 한 결과를 `{ key: { v, conf } }` 형태로 반환하도록 바꾸면 됩니다.
- `FIELDS[].exp` — 모드별 기준값입니다. Normal 모드 기준값은 임시로 MP와 같게 두었으니 실제 규격으로 바꿔 주세요.
- `업로드` 버튼 — 서버 전송은 시뮬레이션입니다. `Excel 내보내기`는 CSV(UTF-8 BOM)를 내려받습니다.
